# 客户 API 产品化交付

`customer-api-productization` 用于把已有业务能力整理成可供外部客户长期接入的 API 产品。交付范围包括接口实现、产品范围、客户契约、凭证与租户、环境隔离、接入材料、测试证据、监控支持和发布治理。

## 什么项目适合

适合以下项目：

- 已有可运行的业务能力，希望开放给多个客户或合作伙伴系统；
- 需要稳定契约、受控开通、沙箱联调、版本管理和长期支持；
- 能定义客户主体、数据权限、动作权限和生产责任；
- 底层流程已基本稳定，至少可以进入受控试点。

不适合以下项目：

- 内部微服务接口或单次项目对接；
- 业务规则、状态和责任仍在频繁变化；
- 只想自动生成 OpenAPI、接口文档或几段 SDK 代码；
- 无法隔离客户数据、测试副作用或生产凭证；
- 无权开放相关数据或真实业务动作。

遇到不适合的项目，Skill 会停在适配评估或事实发现阶段，输出阻塞原因和下一步，不会为了“交付完整”虚构上线材料。

本 Skill 主要面向受控的 B2B 客户或合作伙伴 API。若目标是匿名注册、自助创建应用的公共开发者平台，还要另外建设滥用治理、开发者门户、法律条款、生态运营和规模化支持，不能直接把本 Skill 的 GA 结论当作开放平台就绪。

## 产出

根据项目实际范围，产出并核对：

- API 产品范围、目标客户、开放能力和非目标；
- REST、GraphQL、事件或其它适用协议的机器可读契约；
- 认证、授权、租户、凭证、环境和审计方案；
- 接入指南、错误目录、可执行示例和版本记录；
- 契约一致性、权限、隔离、异常、幂等和安全测试；
- 监控、告警、支持、开通、回滚和废弃方案；
- 从产品规则到运行实现和测试证据的追溯关系。

## 使用方式

在 Codex 中提出类似请求：

```text
使用 $customer-api-productization 评估当前项目是否适合开放客户 API；适合的话，建立受控试点交付包。
```

也可以指定模式：

- `ASSESS`：只做适配和成熟度评估；
- `BASELINE`：建立第一套客户 API 产品化基线；
- `EXPAND`：扩展已有 API；
- `HARDEN`：在试点或正式开放前审查并补齐。

## 结果状态

- `ASSESSMENT_COMPLETE`：适配评估完成；
- `PILOT_PACKAGE_READY`：受控试点交付包就绪；
- `GA_PACKAGE_READY`：规模化开放交付包就绪；
- `EVIDENCE_BLOCKED`：关键事实、授权或验证仍缺失。

交付包就绪不等于已部署或已开通生产。发布、迁移、客户通知和正式环境启用仍需单独授权。
