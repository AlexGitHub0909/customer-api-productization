# 集成安全模式

## 写操作与幂等

- 对客户端可能因超时重试的创建、付款、提交或触发动作定义幂等键；
- 幂等范围至少包含客户、环境、操作和键；
- 同键同请求返回已有结果，同键异请求稳定拒绝；
- 数据库优先保存键哈希或等价安全表示，避免日志泄露业务关联信息；
- 并发请求必须依赖原子约束、锁或占位记录，不能只在应用层先查后写；
- 不把业务参考号默认为幂等键，除非产品明确保证其唯一和不可变。

## 外部或异步写入

把结果分为明确成功、明确失败和未知。未知状态必须进入查询、对账或人工核查；禁止自动重复不可逆 POST。

本地业务事务和外部写入无法原子提交时，明确先后顺序、补偿边界和事实所有权。外部失败是否回滚本地事实应由产品规则决定，不由通用异常处理猜测。

## 沙箱

沙箱至少满足：

- 客户可见字段和错误尽量与生产同构；
- 每个客户的数据隔离；
- 可解释、可重复或可控制的模拟结果；
- 状态变化、事件和文件能够形成完整闭环；
- 不写生产表、不触发真实收费、不发送真实业务通知、不调用真实上游写入；
- 支持重置、暂停、审计和版本识别。

随机 mock、全局共享样例或“生产表加 sandbox 标记”通常无法满足隔离要求。

## Webhook 与事件

- 使用稳定 `event_id` 和业务去重键；
- 签名覆盖时间戳和原始请求体，并限制可接受时间窗口；
- 客户必须按事件 ID 幂等消费，不能假设只投一次或严格有序；
- 事件和投递意图与业务状态原子记录，或提供可证明的不丢失机制；
- 保留投递目标、订阅和签名上下文的事件时快照，避免配置变化改写历史意图；
- 明确成功、明确失败和结果未知的重试策略；
- 日志和运营页面不显示完整 endpoint 查询、签名密钥或外部原始敏感响应；
- 撤销与普通暂停语义分开，历史审计不可消失。

接收客户配置的回调地址时，还要防止服务端请求伪造：拒绝内嵌账号密码、回环、私网、链路本地、保留地址和不允许的协议；明确 DNS 解析、重定向、端口和出站网络策略，避免只在保存 URL 时校验一次而发送时失效。

## 受保护文件

- 列表只返回客户有权看到的文件摘要；
- 下载时重新鉴权、限流和审计；
- 不返回内部路径、永久公开 URL 或上游临时链接；
- 校验文件归属、可见性、状态、MIME 和大小；
- 外部存储迁移不应改变客户契约。

## 密钥和凭证

- 长期共享密钥或静态 API key 的明文仅在签发或轮换时返回一次；短期 OAuth token、mTLS 证书和签名请求按各自生命周期处理；
- 无需恢复的静态密钥在服务端保存不可逆哈希，必须恢复的签名材料使用受控加密；
- 支持轮换、暂停、不可逆吊销和客户级熔断；
- 日志、异常、追踪、示例、截图和前端状态均脱敏；
- 沙箱和生产凭证不能混用。
