# 质量门禁

## 试点必过门禁

| ID | 门禁 | 合格证据示例 |
|---|---|---|
| `FIT-01` | 项目适合产品化 | 适配结论、目标客户、复用场景、硬阻塞核对 |
| `OWN-01` | 责任明确 | 产品、工程、运营、支持和审批责任人 |
| `SCOPE-01` | 产品范围闭合 | 开放能力、非目标、真实副作用和客户承诺 |
| `CONTRACT-01` | 机器契约有效 | 当前契约通过对应解析器或校验器 |
| `CONTRACT-02` | 运行时与契约一致 | 请求、响应、错误和下载类型的一致性检查 |
| `AUTH-01` | 凭证与授权安全 | 签发、轮换、暂停、吊销、scope 和脱敏测试 |
| `SECURITY-01` | 安全模型经过验证 | 对象级授权、滥用、输入、回调、文件、重放和敏感信息威胁及测试 |
| `TENANT-01` | 租户隔离 | 跨客户资源、列表、文件和事件的负向测试 |
| `DATA-01` | 数据可见性闭合 | 敏感字段清单与响应、日志、页面防泄露测试 |
| `GOVERNANCE-01` | 治理授权闭合 | 隐私、合规、数据保留、上游授权及适用商业条款已确认 |
| `ENV-01` | 联调环境安全 | 沙箱与生产字段对齐、数据和副作用隔离证据 |
| `ERROR-01` | 错误稳定可处理 | 稳定错误码、协议状态、客户消息和重试建议 |
| `RETRY-01` | 重试和幂等安全 | 重放、同键异参、并发、超时和未知结果测试 |
| `DOCS-01` | 接入材料可执行 | 指南、示例或集合在隔离环境完成闭环 |
| `TEST-01` | 风险测试通过 | 正向、负向、边界、安全和回归当前执行记录 |
| `OPS-01` | 可观测可支持 | 请求标识、日志、指标、告警、支持和熔断 |
| `CAPACITY-01` | 容量与依赖有边界 | 超时、限流、负载、配额、依赖故障和目标服务水平证据 |
| `RELEASE-01` | 发布边界明确 | 版本、变更记录、开通门槛、停止和回滚条件 |
| `ACTIVATION-01` | 生产动作独立授权 | 交付、部署、开通和客户通知分别记录 |
| `TRACE-01` | 关键规则可追溯 | 产品规则映射到契约、实现、测试、接入和运维材料 |

## 条件门禁

只有相关能力存在时才要求：

- `WEBHOOK-01`：签名、事件幂等、投递记录、重试、未知结果和配置变更语义；
- `ASYNC-01`：异步任务状态、查询、超时、去重、补偿和人工收口；
- `FILE-01`：文件归属、可见性、下载鉴权、MIME、审计和存储隐藏；
- `BATCH-01`：批量大小、部分成功、错误明细、重放和资源限制；
- `SDK-01`：语言选择依据、生成或手写策略、版本、发布、安全响应和兼容测试。

不存在该能力时可 `not_applicable`，并写明原因。能力存在但尚未实现时必须 `fail`，不能标记不适用。

## GA 附加门禁

- `PILOT-01`：至少一个受控客户完成端到端接入，或完成等价的生产级演练；
- `SUPPORT-01`：支持时段、告警接收、升级路径和客户沟通经过确认；
- `DEPRECATION-01`：兼容规则、迁移窗口、废弃通知和旧版本观测可执行；
- `ROLLBACK-01`：回滚、停用、凭证吊销和数据收口经过演练或有可验证证据。

## 判定规则

- `pass` 必须附可定位的当前证据；
- `fail` 必须说明影响、责任人或下一步；
- `not_applicable` 必须说明为什么产品不包含该能力；
- 证据文件存在但内容与门禁无关，不算通过；
- 校验器通过只证明清单结构和引用完整，不能替代逐项审查。

执行型门禁不能只引用设计文档：

- 契约有效性使用 `contract_check`；
- 运行时一致性使用 `runtime_check`；
- 测试、安全和隔离使用 `test_run` 或 `security_review`；
- 示例闭环使用 `example_run`；
- 容量使用 `performance_check`；
- 受控试点使用 `pilot_run`；
- 回滚使用 `operations_record`。

上述证据必须记录带时区的实际观察时间，并绑定清单中的源版本和审查范围。
